================================================================================
  3. PERCHE LA CARTELLA src/ HA SENSO
================================================================================

Separare CONFIG (root) da CODICE (src/) e una convenzione comune:

  reactnextjs/
    next.config.ts      <- configurazione framework
    tsconfig.json
    package.json
    public/             <- Next lo serve fuori da src
    src/                <- TUTTO il codice applicativo

Vantaggi:
  - Confine chiaro: "tutto cio che scriviamo noi sta in src/"
  - server/ non si confonde con node_modules o file di build
  - Scalabile quando aggiungi auth, admin, prenotazioni
  - Allineato a create-next-app con opzione --src-dir

Next.js si aspetta:
  - src/app/     (non app/ alla root) se usi src
  - public/      sempre alla root del progetto Next

  5. ARCHITETTURA A STRATI (regola da non infrangere)
================================================================================

                    REQUEST HTTP
                         |
                         v
              +---------------------+
              |  app/api/.../route  |  Adapter Next (5-20 righe)
              |  export GET/POST... |
              +----------+----------+
                         |
                         v
              +---------------------+
              |     CONTROLLER      |  getMovies, putGenere, postLogin
              |  *.controller.ts    |  nomi leggibili, niente Mongo
              +----------+----------+
                         |
                         v
              +---------------------+
              |      SERVICE        |  validazione, regole, relazioni
              |   *.service.ts      |  "genereIds devono esistere"
              +----------+----------+
                         |
                         v
              +---------------------+
              |    REPOSITORY       |  find, create, update, delete
              |  *.repository.ts    |  solo query Mongoose
              +----------+----------+
                         |
                         v
              +---------------------+
              |       MODEL         |  schema collection Mongo
              |    *.model.ts       |
              +---------------------+
                         |
                         v
                     MongoDB

FRONTEND (parallelo, mai salta i layer):
  Page/Component  -->  lib/api-client  -->  fetch("/api/...")  -->  stesso flusso sopra

COSA NON FARE
  - Mongoose dentro components/ o page.tsx client
  - Logica business dentro app/api/route.ts (solo try/catch + chiamata controller)
  - Un file unico "backend.ts" con tutto dentro
  - Service che importano Request/Response di Next


================================================================================
  6. UI vs API: /film vs /api/movies (naming)
================================================================================

Oggi:
  - URL pagina utente:  /film
  - URL API REST:       /api/movies

E' accettabile e comune:
  - UI in italiano / brand (/film, /prenotazioni, /profilo)
  - API in inglese REST (/api/movies) - standard JSON API

Alternativa (uniformare tutto):
  - rinominare pagine in /movies oppure API in /api/film

CONSIGLIO: tieni /film per UI e /api/movies per API.
Documentalo e non mescolare i due mondi:
  - src/app/film/           = cosa vede l'utente
  - src/app/api/movies/     = contratto dati per frontend/admin

SICUREZZA
