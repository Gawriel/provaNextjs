OBIETTIVO FINALE
----------------
Costruire un'applicazione web completa stile Netflix + IMDb + sito cinema,
da usare come progetto portfolio.

L'utente potra:
  - navigare un catalogo film con filtri, ricerca e ordinamento
  - vedere la locandina / dettaglio di ogni film
  - registrarsi e fare login (JWT)
  - vedere UI diversa da loggato (avatar con iniziali in alto a destra)
  - gestire profilo, preferiti, logout
  - aprire una pagina di streaming finto (/movies/[id]/watch)
  - prenotare posti al cinema (mappa posti colorata)
  - se ADMIN: CRUD completo sui film (sostituisce l'Employee Manager)

Dal punto di vista tecnico si dimostrano:
  Next.js, React, TypeScript, API REST (Route Handlers),
  Mongoose, MongoDB, Login/JWT, CRUD, filtri, ricerca, routing,
  componenti riusabili, stato/context, deploy.


ARCHITETTURA SCELTA
-------------------
Next.js + API Routes (SENZA Express separato).

  Browser (React)
        |
        |  fetch("/api/...")
        v
  Next.js (stesso progetto)
    - app/           -> pagine UI (frontend)
    - app/api/       -> backend REST (Route Handlers)
        |
        v
     Mongoose
        |
        v
     MongoDB

Un solo npm run dev, una sola porta (3000), un solo deploy (es. Vercel)
+ MongoDB Atlas per il database.

ARCHITETTURA A STRATI (OBBLIGATORIA)
------------------------------------
  1. Model       = forma della collection Mongo
  2. Repository  = find/create/update/delete (niente HTTP, niente regole)
  3. Service     = validazione, relazioni, populate, errori 404/400
  4. Controller  = getGeneri / postGenere / putGenere / deleteGenere
  5. app/api     = Next richiede un file per URL: PUT /api/generi/:id
                   chiama putGenere. Non si mette putGenere nel nome del file.

  Perché [id] per OGNI risorsa e non uno solo:
    /api/generi/ABC  e  /api/movies/ABC  sono URL diversi.
    Next mappa le cartelle sugli URL. Un solo [id] sarebbe /api/[id]
    e non sapresti se ABC è un genere o un film.


MODELLO DATI (MongoDB via Mongoose)
-----------------------------------
  Genere       -> nome (unique)
  Persona      -> nome, bio, foto, ruoli[] (attore e/o regista)
  Movie        -> titolo, descrizione, anno, durata, poster, trailer,
                  streaming, generi[ObjectId], registi[ObjectId],
                  attori[ObjectId]
  (futuro)
  User         -> nome, email, passwordHash, role (USER | ADMIN)
  Favorite     -> userId + movieId
  Review       -> userId + movieId + voto + commento
  Reservation  -> userId + movieId + cinema + data + posti

COME COLLEGARE UN FILM AD ATTORI/REGISTI/GENERI
-----------------------------------------------
  1. POST /api/generi     { "nome": "Azione" }           -> id genere
  2. POST /api/persone    { "nome": "Nolan", "ruoli": ["regista"] }
  3. POST /api/persone    { "nome": "DiCaprio", "ruoli": ["attore"] }
  4. POST /api/movies     {
       "titolo": "Inception",
       "descrizione": "...",
       "anno": 2010,
       "durata": 148,
       "poster": "",
       "trailer": "",
       "streaming": "",
       "genereIds": ["ID_GENERE"],
       "registaIds": ["ID_NOLAN"],
       "attoreIds": ["ID_DICAPRIO"]
     }

  Il film NON copia i nomi. Salva solo gli id.
  In GET, Mongoose populate() riempie attori/registi/generi con i documenti.

  FASI DI LAVORO (ORDINE CONSIGLIATO)
================================================================================

NON partire dal login. Ordine:

  FASE 1 - Catalogo statico
    Imparare Next, routing, componenti, layout, filtri UI.
    Dati da array/JSON locale (data/movies.ts). Niente DB.

  FASE 2 - MongoDB + Prisma
    Collegare il database. I film arrivano da Mongo (ancora senza API
    complete se si vuole leggere via server component, oppure subito API).

  FASE 3 - API Routes film
    CRUD REST in app/api/movies. Frontend fa fetch("/api/movies").

  FASE 4 - Admin CRUD (senza auth)
    Pagine admin per aggiungere/modificare/eliminare film.
    Capire il Movie Manager puro.

  FASE 5 - Login / Registrazione / JWT
    Proteggere operazioni admin e personalizzare l'utente.

  FASE 6 - Profilo, avatar iniziali, preferiti
    Context utente, header fisso con iniziali, logout.

  FASE 7 - Streaming finto
    /movies/[id]/watch con player mock (YouTube trailer o video locale).

  FASE 8 - Prenotazione cinema
    Scelta cinema -> orario -> posti (mappa) -> prenota.

  FASE 9 - Deploy
    Vercel (app) + MongoDB Atlas (DB). Portfolio online.
